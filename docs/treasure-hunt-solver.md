# オタカラ探しソルバー設計

外部サイトのソース、HTML、CSS、UIは使用せず、ゼロから実装しています。

1. 指定された幅・高さの宝について、盤面内に収まる全配置を列挙する。
2. 「空白」を含む配置を除外する。
3. 宝どうしが重ならない組み合わせを深さ優先探索する。
4. 「宝ヒット」「発見済み」がすべて含まれる組み合わせだけを有効候補にする。
5. 各未確認セルを含む候補数 ÷ 全候補数で存在確率を計算する。
6. 確率順の上位5マスと同率最高マスをすべて表示する。

盤面入力は「未確認」「空白」「宝ヒット」「発見済み」から状態を先に選び、タップしたマスへ直接設定します。循環切替は行いません。発見済みは宝がある必須マスとして探索し、残りツルハシ概算から除外します。

宝形状は1×1〜4×4の16種類をすべて表示し、形状カードを押すたびに1個追加、各形状の「−」で1個減らします。個数は形状ごとに0〜3個です。幅×高さは明示された向きのまま扱い、4×2を2×4へ自動回転しません。選択内容は `4x2:2, 1x3:1` 形式へ同期します。上級者向けtextareaへ入力した内容も、16種類・0〜3個・重複なしで解釈できる場合は形状UIへ戻し、それ以外は特殊specとして維持します。

入力モード、確率表示、おすすめ強調、自動再計算、16形状の個数を既存キー内のversion 3として保存します。version 1・2の盤面とspecは移行してそのまま読み込めます。「宝設定をクリア」は形状と個数だけを0へ戻し、盤面、Undo履歴、その他設定は変更しません。

組合せ爆発を避けるため有効候補は20,000件で打ち切り、その場合は必ず概算と表示します。入力とUndo履歴は個人情報を含まず、現在盤面と表示設定だけをlocalStorageへ保存します。Analyticsにはツール名と操作種別だけを送り、盤面内容、開けたマス、宝位置、宝specは送りません。
