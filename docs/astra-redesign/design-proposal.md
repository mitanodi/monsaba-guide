# Astra autonomous redesign — design proposal

2026-09-15 / 実装前の設計判断。Production control: `6111788e392892c19a4452a3fb186cc97fc8bd45`。

## 1. Site goal
「今日やることと、次に育てるタタが決まる」非公式攻略ワークスペース。データ量を入り口の多さで表現せず、検索・予定・判断・実践に整理する。

## 2. Target users
初日から数日の初心者、進化投資を判断する中級者、モード別の編成を反復するプレイヤー。閲覧者の個人情報や未取得Analyticsで人物像を捏造しない。

## 3. Main user journeys
今日の予定→開催イベント攻略。名前検索→タタ詳細→進化差分→比較→編成。初心者→ゲーム進行→育成候補→手持ち登録。編成→保存・共有→Communityで結果確認。

## 4. Information architecture
ホームはダッシュボード、図鑑はホーム内の独立した作業領域（既存 `/#tatari` を保持）。Tier・育成・イベント・ツール・Communityを明確に分離。`/events/calendar/` は現行soft 404のため、新たに実体を作る。既存URLは移動しない。

## 5. Navigation
Desktopは左側にホーム・図鑑・Tier・カレンダー・編成・初心者・Communityの直通リンク、その下に既存カテゴリを置く。ヘッダーはブランド、検索、言語。Mobileは5項目（ホーム・図鑑・Tier・予定・編成）、検索はヘッダーから常時アクセス。カテゴリメニューは開閉とEscape、フォーカスを検証。

## 6. Home layout
控えめな非公式表記とゲームの正式素材を使った短い導入→今日／次回の予定→検索可能な図鑑→育成とモード攻略→更新／Community／情報方針。重複する目的別CTAは折りたたみ・整理。元の主要本文・H1は静的HTMLとして保持。

## 7. Tata DB
実データ65系統236体。画像・正式名・属性・評価の四点に揃えたカード。検索とソートを図鑑の直上へ移す。属性/T4フィルター、選択解除、結果件数、コンパクト表示を保持・改善。スマホ2列、PCは利用可能幅に応じ4〜6列。

## 8. Tata detail
画像・総合評価・役割→何に強いか／どこで使うか→育成の根拠→進化→スキル詳細。既存独自評価と確認済み数値を改変しない。保留は保留。倍率・出典を含む本文は削除しない。比較／編成／手持ちへの連続した導線を維持。

## 9. Tier
説明より画像Tier表を先に。説明は開ける。順位は固定し、既存モード切替・属性・絞り込みを維持。独自評価というラベルを表の近くへ置く。

## 10. Beginner
何をする→何を育てる→どこまで→どこで使う、を4つの短い段階リンクで表示。既存攻略根拠を保持し本文の読み幅を制限。手持ち登録へのCTAは文脈に沿って配置。

## 11. Team Builder
盤面中心のワークスペース。Desktopは盤面と選択一覧を同時表示。編成名・高度な設定は開閉可能。モードは常時選べる。既存5モードの盤面サイズ、上限、Player、チップ、share codec、mode draftをそのまま使用。Mobileの選択パネルは画面下部のsheetとし、閉じるボタン、Escape、フォーカス管理、タップ代替を検証。

## 12. Community
投稿0件を正直に表示し、編成を作る→条件を記録→結果を共有という利用価値を静的に伝える。偽の投稿・人数・実績を表示しない。実験版APIは閲覧専用にし、投稿等の更新はサーバー側でも拒否。

## 13. Events
イベント攻略を探すハブ。現在と次回の短い予定カードから攻略へ。月全体の巨大カレンダーは独立ページへ移す。確認状態を保持。

## 14. Calendar
独立URLで今日／次回イベント／次回Boss、終了日時を先頭に表示。既存calendar-coreとconfigを単一情報源として使う。チーム09:00 JST、Boss00:00 JSTの境界を保持。未確認アンカーを捏造しない。Mobileは月内の日程を縦の一覧でも読めるようにし、横スクロール依存を解消。

## 15. Search
既存検索エンジン／グローバル検索を維持。ヘッダーに常設。検索履歴は端末内、検索語をAnalyticsへ送信しない。検索画面にタタ・攻略・スキルの用途説明と回遊リンク。

## 16. Mobile
390pxを主基準、320/375/430/768も確認。操作は44px以上を目標。長い日本語・EN・zh-CNを折り返す。固定要素が盤面と重ならないことを実操作で確認。物理iPhoneの指触りはHuman Verification。

## 17. Desktop
左ナビ216px、本文最大1280px。1920pxでも無意味に本文を長くしない。青いブランドの継承と濃紺のナビで情報の階層をつくる。記事とツールの最適幅を分ける。

## 18. Monetization
BALANCEDを採用候補。記事の読了後・関連コンテンツ境界が中心。ツール、検索、Calendar、Community、Board、Friendsは広告なし。Previewは明確な「広告 / PR」placeholderのみ。`?ads=off`／`?ads=preview`で比較。A8コード・案件・AdSense accountは変更しない。

## 19. SEO
既存canonical/hreflang/robots/H1/構造化データ/URLを比較検証。独立Calendarのみ追加。PreviewはHTTP X-Robots-Tagでnoindex。既存本文をSSR化せず、静的生成のままにする。生成処理は冪等な最終変換として統合し、promoには適用しない。

## 20. Performance
Framework追加なし。HTML変換用のCheerioは開発依存のみ。画像の追加転送を避け、公式の既存WebPを使う。追加CSSは圧縮前25KB以内、共通追加JSは12KB以内を初期予算。日付ロジックは必要ページだけで読み込む。実広告・AnalyticsはPreviewではネットワーク起動させない。Before/After転送量とlab LCP/CLSを計測し、実ユーザーINPを計測したと偽らない。

## Review loops
V1：全体構成・静的生成。V2：同条件のブラウザ操作・画像・overflow・a11yから修正。V3：Previewで再操作・SEO/回帰/性能検証から修正。見た目だけで合格にしない。
