# Tier data maintenance

`data/tata-tier.json` is the editable source of truth for all 65 families and
five independent editorial rankings dated 2026-09-16. Do not calculate overall
ratings from mode scores. Canonical IDs, names, links and images come from the
existing Tatari and image catalogs.

- Edit `rankings.overall`, `normal`, `zombie`, `dojo`, or `beginner` in that file.
- Ranks: SSS, SS, S, A, B, C, D, HOLD. HOLD is explicit, never a missing value.
- Preserve `status` and `rawEvaluation`. This edition has 3 HOLD and 8 provisional evaluations.
- `order` is optional per mode; the overall order is the fallback and tie-break.
- UI translations live in `data/i18n/tata-tier.json`. Character names always use the existing localized catalog.
- Run `npm run generate:tier`, `npm run test:tier`, and `npm run validate`.
- `node scripts/generate-tier-pages.mjs --check` checks reproducibility without writing files.

`data/tier-ratings.json` is a generated compatibility view for existing consumers;
do not edit it manually. The generator updates all three Tier pages, existing
detail-page ratings, and compact home/evolution-guide badges. Its shared renderer
is `scripts/lib/tier-board.mjs`; JavaScript only enhances the attribute filter.
All five boards are present in the initial HTML.

The full site generation pipeline also invokes the Tier generator before data
consumers and after localization/layout generation. Full-site regeneration on the
starting commit `842f0979` already changed unrelated generated pages, including
advertisement placements. This work keeps those unrelated outputs out of the
change. Validate Tier reproducibility separately rather than committing unrelated
whole-site generation drift.
